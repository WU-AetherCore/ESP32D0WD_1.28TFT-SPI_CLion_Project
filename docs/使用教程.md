# ESP32-D0WD 圆屏仪表盘：从克隆到运行

本文按一台新 Windows 电脑说明。工程面向经典 ESP32-D0WD + 240×240 GC9A01 屏幕，不是 ESP32-S3 固件。不同批次开发板引脚可能不同；若你的板子与本项目接线不一致，请先对照原理图再上电。

## 一、准备软件

1. 安装 Windows 10/11 64 位版 [CLion](https://www.jetbrains.com/clion/)（可使用试用版或有效许可证）。
2. 在 CLion 设置里打开 **Plugins**，安装 PlatformIO 插件并重启 CLion。首次启动 PlatformIO 等待它安装 PlatformIO Core。
3. 安装 [Python 3.10 或更高版本](https://www.python.org/downloads/windows/)，安装界面勾选 **Add Python to PATH**。
4. 把板子接到 USB。若 Windows 设备管理器没有出现 `COMx`，先安装这块板所用 USB 转串口芯片的官方驱动，然后重新插拔并确认端口号。
5. Git 克隆本仓库，或在 GitHub 页面选择 **Code → Download ZIP** 并解压。目录路径尽量使用英文和短路径。

## 二、用 CLion 打开、编译和烧录

1. CLion 选择 **File → Open**，选仓库根目录（可看到 `CMakeLists.txt` 和 `platformio.ini`）。
2. 出现 CMake Presets 选择时，选 `ESP32D0WD`。如果没有弹出，进入 **Settings → Build, Execution, Deployment → CMake**，重新加载 CMake 项目。
3. 首次配置会下载 ESP32 平台、Arduino 框架和库，等待完成。工程需要 PlatformIO Core 位于 `%USERPROFILE%\.platformio`。
4. 构建：在 CLion CMake target 里运行 `firmware`，或双击 `build.cmd`。命令行也可以运行 `build.cmd`。
5. 打开板上电源并连接 USB。设备管理器 → **端口（COM 和 LPT）**确认端口号，比如 `COM7`。
6. 运行 `flash.cmd COM7`。首次烧录或串口自动复位失败时，按住开发板上的 **电源键**直到开始连接/擦写，然后松开；电源键是电源控制，不是用户按键。
7. 运行 `monitor.cmd COM7` 可打开 115200 波特率串口监视器。退出串口监视器使用 `Ctrl+C`。

也可在 CLion 的 CMake build preset 选 `firmware` 编译，选 `upload` 编译并烧录。烧录时不要让串口监视器占用同一个 COM 口。

## 三、第一次配网与自动重连

1. 烧录后给开发板供电，屏幕会显示配网状态。使用手机或电脑的 Wi-Fi 列表连接 `D0WD-Dashboard-Setup`。
2. 连接后浏览器打开 `http://192.168.4.1`。输入路由器的 2.4 GHz Wi-Fi 名称和密码并提交。家庭路由器的 2.4 GHz 与 5 GHz 可能共用名称；如果连接不稳定，建议先启用一个独立的 2.4 GHz SSID。
3. 设备把 Wi-Fi 名称和密码保存至 ESP32 的 NVS 非易失存储。重启或断电不会清除，下次启动自动尝试连接；掉线后固件会周期性重连。
4. 配网状态含义：
   - **无线连接中**：正在加入路由器。
   - **已保存网络重试中**：已有已保存凭据，暂时无法加入；设备仍继续重试并开放配网入口。
   - **无线已连接等数据**：路由器已连接，尚未收到电脑状态包。
   - **电脑数据已连接**：最近收到电脑发来的数据。
5. 配网页面显示的路由器地址或串口 `INFO` 输出可用于排查。路由器开启客户端隔离时，即使设备都连着 Wi-Fi，也无法相互收发 UDP；请关闭访客网络/无线隔离，或把二者接入同一普通局域网。

想换网络，可重新连接配网热点提交新凭据。也可以串口发送 `SETWIFI,WiFi名称,WiFi密码`。若密码中包含逗号，请使用网页配网。清除已保存网络：同时按住两个用户按键约 5 秒；确认开发板确实有两个用户按键，电源键不参与此操作。

## 四、电脑状态采集端

电脑端脚本每秒采样并通过 UDP 4210 广播，不保存 Wi-Fi 密码，也不需要长连 USB。ESP32 和电脑必须在相同的普通局域网；它们仍然都需要电源/电池。

1. 双击 `run_pc_monitor.cmd`。首次运行会自动用 PlatformIO Python 环境或系统 Python 安装 `requirements.txt` 里的 `psutil`。
2. 命令窗口出现“正在通过…发送局域网数据”以及 CPU、内存等行，说明采集脚本已经开始广播。首次授权 Windows 防火墙时，允许 Python 在**专用网络**通信。不要为了此功能向公网开放端口。
3. 等待约 1–2 秒，屏幕状态应从“无线已连接等数据”切换为“电脑数据已连接”。如果电脑在多个物理网卡上有网络，脚本会对检测到的网卡广播地址发包。
4. 若自动广播不通，可将路由器分配给仪表的 IP 写入本机 `dashboard_ip.txt`（纯文本，只写 IP，例如 `192.168.1.100`），再重启 `run_pc_monitor.cmd`。该本机配置文件被 Git 忽略，仓库提供的 `.example` 仅作格式参考。也可在终端执行：

   ```powershell
   py -m pip install -r requirements.txt
   py tools\pc_monitor.py --broadcast 192.168.1.100
   ```

5. 确认电脑没有连访客 Wi-Fi、VPN 或开启客户端隔离；如果 UDP 仍不通，在 Windows Defender 防火墙的“允许应用通过防火墙”中允许使用的 Python 在专用网络通信。随后检查串口 `INFO` 的 UDP 接收计数是否递增。
6. 停止电脑端采集，在命令窗口按 `Ctrl+C`。

### 指标来源与限制

| 指标 | 来源 | 备注 |
|---|---|---|
| CPU 负载 | Windows `GetSystemTimes` 相邻采样差值 | 约每秒更新 |
| 内存 | `GlobalMemoryStatusEx` | 物理内存已用比例及容量 |
| CPU 温度 | LibreHardwareMonitor / OpenHardwareMonitor WMI | 仅可信 CPU 封装/核心传感器；无提供程序时显示不可用 |
| 网络下行/上行 | `psutil` 的网络适配器累计字节差值 | 流量空闲显示 0.00 MB/s 是正常值；当前采样从选中的活动物理网卡计数 |
| 系统盘 | Windows 系统盘容量 | 容量单位 MB |
| 电脑运行时间 | Windows `GetTickCount64` | 不等于当前登录时长 |

## 五、按键、截图与串口诊断

- SW1：下一页；SW2：上一页。也可以等待自动轮播。
- `tools/capture_all_pages.py COM7`：临时显示六页测试数据并保存截图，便于布局检查；仅供演示，随后重启会回到正常采集状态。
- `capture_tft.cmd COM7`：保存固件绘制帧镜像。圆屏没有像素读回线路，不能据此确认 LCD 玻璃的实际电气显示状态。
- `INFO`：显示运行、PSRAM、UDP 收包和绘制统计。
- `SCAN`：扫描无线网络。
- `PAGE,0` 到 `PAGE,5`：切换页面。
- `SETWIFI,ssid,password`：写入并保存路由器凭据。

发送命令可用 `monitor.cmd COM7`，在串口监视器中输入命令并发送。串口截图工具需要关闭其他正在占用 COM 口的程序。

## 六、常见问题

### 屏幕黑屏或只有背光

检查供电、屏幕线序、GPIO 与本项目硬件表是否一致；查看串口启动日志；确认固件烧录到了正确端口。不同板型即使屏幕外观相同，CS/DC/RESET/SPI 线也可能不一样。

### CLion 找不到 PlatformIO 或 CMake 配置失败

在 CLion PlatformIO 插件里确认 PlatformIO Core 安装完成；检查 `%USERPROFILE%\.platformio\penv\Scripts\pio.exe` 和 `python.exe` 是否存在。可从 CLion 重新加载 CMake，再运行 `build.cmd` 看第一条错误。

### 烧录提示端口忙/连接失败

关闭 CLion 串口监视器、Arduino IDE、串口助手等占用 COM 的程序；拔插 USB，在设备管理器重新确认端口；按板上的电源键使设备进入正常上电状态，再运行烧录命令。

### Wi-Fi 一直重试

确认 SSID 和密码大小写正确，连接的是 2.4 GHz 网络且没有强制门户；靠近路由器，检查路由器 DHCP 是否成功分配地址。若设备已保存旧密码，通过配网热点重新提交或用 `SETWIFI` 更新。

### 屏幕收到 Wi-Fi 但没有电脑数据

确认电脑脚本窗口仍在运行且显示发送行；电脑与仪表需在同一子网；关闭客户端隔离；允许 Python 在 Windows 专用网络通信；用路由器地址单播测试，并观察 `INFO` UDP 收包数。

### CPU 温度显示不可用

Windows 通常不提供可靠的 CPU 封装温度。安装并运行 LibreHardwareMonitor（或 OpenHardwareMonitor），确认其显示了 CPU Package/Core 传感器。脚本每 15 秒读取一次 WMI，查不到时保持“不可用”。

### 网络速率总是 0

空闲时 0 是正确值。测试时让电脑实际下载/上传数据；确认被选网络适配器是当前联网的物理网卡，而不是虚拟 VPN。如果多个物理网络同时处于活动状态，速率统计可能与实际路由出口不一致。

## 七、再次打开和调试

拿到这份工程后无需拷贝 `.pio` 或 `cmake-build-*`。CLion/PlatformIO 会按 `platformio.ini` 重新获取依赖；CMake 使用工程内的 `CMakePresets.json`。修改固件源码后重新运行 `firmware` 构建，连接 USB 后运行 `upload` 或 `flash.cmd COMx`。电脑采集端保持独立运行，换电脑时重新安装 Python 依赖即可。
